## 4. 关键坑（都是踩过的）

1. **菜单有存栏时，第一项是「继续游戏」**。点它验证"新开局"会拿到旧 run 的牌组（15 张旧卡），曾让我误判牌组代码坏了。验证新开局必须先删 `current_run.save` 并确认菜单是「单人模式」布局（无存栏时 y≈708，有存栏时 继续=675 / 放弃=719）。
2. **`countuse` 日志只对自家卡触发**（驱动/脉搏急救/撑住/喂食…）。原版打击/防御不会打印，用原版卡测"空放"永远没日志。
3. **日志是缓冲写入**（8KB/1s，异常行立即刷）。抓日志前等 3–5 秒，或连发两次命令。
4. **启动要预热约 90 秒**再点击，否则菜单/选人页点击会丢。
5. **AutoSlay 必须在主菜单（「单人模式」布局）启动**。有存栏时先在菜单点「放弃当前游戏」→ 弹窗点「好的」清档；只删 `current_run.save` 不可靠（实测重启后游戏又恢复了存档）。从房间内启动会直接 `PlayMainMenuAsync` 超时。
6. **`win` 调试命令**只把敌人打死，战斗有时不会自动结算；要真正结算需手动出牌打死或结束回合。
7. **`t:play:<ID>` 不出牌**（主线程调 `TryManualPlay` 无效），要出牌只能拖拽或点击。
8. **构建必须用 .NET 9 SDK**。本机系统只有 SDK 8，`dotnet build` 直接 `NETSDK1045`。已装 9.0.320 到 `/home/firefly/dotnet9`：
   `/home/firefly/dotnet9/dotnet build zhiji.csproj`。
   **不要用 csc 手编**：缺 Godot 生成代码，`_Process` 之类脚本方法不派发，会制造"立绘不刷新/命令部分失效"的假象（本次浪费了一轮排查）。
9. **`EnsureWatcher` 的 Timer 必须 `Autostart = true`**（3.3.52 已修）。即使修了，`OverlayWatcher._Process` 在延迟挂载路径下仍不一定 tick，所以**房间门控必须挂到 debug pump**（0.25s 的 SceneTreeTimer 自排），不能只依赖 watcher。
10. **战斗结算/死亡后必须抑制 pump**（`Visuals.SuppressOverlay`），否则 0.25s 后立绘会被重新弹回奖励页/死亡页，直接回退 W5。抑制在换房间时自动解除。
11. `t:kw` 实际**能**出日志（旧文档说不能是错的）：`t:kw PREPARE kw=[Exhaust]`。
